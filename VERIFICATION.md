# Проверка разделённых проектов

Проверки выполнены локально, без рабочих ключей и без изменения вашей базы.
Среда проверки Node.js 24; Dockerfile и .nvmrc фиксируют Node.js 22, сборки ориентированы на node22.

## Пройдено

- Чистый npm ci --include=dev для backend и frontend с отдельными lockfile.
- TypeScript обоих проектов: 0 ошибок.
- Production build каждого проекта: успешно.
- Backend: 11 автоматических тестов — маршруты, auth proxy, роли, запрет неизвестных
  RPC, Origin, ограничения доступа к проектам, валидность дерева и WebSocket.
- База: выполнен полный database/install-new.sql из 60 миграций в PGlite PostgreSQL.
  Проверены создание четырёх bucket, приватность guide-files, изоляция задач двух
  пользователей, админский доступ, запрет изменения собственной блокировки/роли,
  запрет клиентского доступа к hub_projects и отказ заблокированному пользователю.
- Frontend: 3 теста; в том числе пути файлов гайдов и отсутствие запроса для пустого списка.
- Hosting frontend: 2 теста; фиксированный upstream, сохранение пути API, multipart,
  Origin/Authorization, статусов HTTP, маршрутов SPA и кеширования assets.
- Совместный запуск двух реальных Node-процессов из собранных проектов: health обоих,
  запрос входа через оба прокси, 401 без сессии, прямая загрузка /projects и /task/123,
  ответ подписанного файла и настоящий WebSocket через оба сервиса к тестовому upstream.
- Побайтовое сравнение всех 91 исходных TSX/CSS-файлов с предыдущим архивом: совпадают.
- Поиск удалённых платформенных доменов, SDK, идентификатора старого проекта и встроенных
  JWT в исходниках/настройках: совпадений нет. Рабочих .env в архивах нет.

## Ограничения проверки

PGlite выполняет настоящий SQL приложения, но managed-схемы auth/storage/realtime
в тесте представлены минимальными фикстурами. Это не интеграционный тест настоящих
Supabase Auth, Storage API, Realtime RLS или pg_cron в вашем проекте.
HTTP/WebSocket проверки используют тестовый upstream; они не доказывают корректность
всех сценариев с реальными пользователями/данными.

Docker и Railway deploy не выполнялись: Docker и доступ к Railway отсутствуют.
Настоящие SMTP/Telegram, перенос базы/Auth/Storage и первые админские операции не
выполнялись без ваших ключей. Browser/screenshot-проверка не выполнена: Chromium
не удалось скачать из-за сетевых таймаутов. Внешний вид подтверждён сравнением
исходных компонентов/стилей, а не сравнением скриншотов.

ESLint: 0 ошибок, 24 предупреждения старых компонентов о React hooks/Fast Refresh.
Vite предупреждает о крупном общем bundle. Эти сообщения не блокируют сборку.
Старые RLS-политики перенесены; это не полный аудит безопасности всей исходной базы.

Перед переключением рабочего домена выполните реальные сценарии из START-HERE.md.
